## 1. 当前架构（第一步产物）

```
客户端（每个装了 mod 的客户端各跑一份，逻辑完全相同）
└─ SwordPlayerModelHandler（ClientTickEvent.Post，遍历 level 内全部玩家：本地+远程）
   ├─ 激活条件：主手持自定义铁剑 且 主手为右手（均为 vanilla 同步状态）
   │   └─ activate：setModel((entity, modid:player_wrist))
   │       → WristSkinComposer 合成 96×64 动态贴图（玩家本人皮肤 64×64 + 剑 32×64）
   │       → setTextureLocation → 播 3rd_still(MAIN) + 状态动画(STATE)
   ├─ 看门狗（每 tick）：
   │   ├─ 挥击上升沿 → stopAnimation(MAIN) + 3rd_attack(once)；播完恢复 3rd_still
   │   ├─ 状态切换：!onGround ? (vy>0.1→jump : fall) : (水平速度>ε→move : idle)
   │   └─ 皮肤位置变化 → 释放+重合成；合成失败每 20 tick 重试
   └─ deactivate（卸剑）：stopAllAnimation + setModel(默认索引)  ← 本次修复点
```

- 模型 `player_wrist`：24 骨（分段身体 steve.json 1:1 + 剑骨树经 A·p+B 嵌入手腕），96×64 复合贴图。
- 渲染模式 = Spark 模式③（全替换）：`PlayerRendererMixin` @HEAD 见 `model!=null && !modelIndex.isPlayer()`
  → `ci.cancel()`，整个 PlayerRenderer 被 Spark 模型渲染取代（原版手持物品层一并消失，所以剑必须嵌入模型）。
- 动画分组：STATE=1（身体，看门狗+Spark 内置状态机共驱）、MAIN=4（剑，3rd_still/3rd_attack）。
  单组单骨规则：同骨被两组驱动时后迭代组整体覆盖（不混合）→ 右臂留给第二步抬臂专用组。
- 资源位置：mod 资源 `spark_models/entity/<modid>/player_wrist.json`、
  `spark_animations/<modid>/entity/player_wrist/*.json`、`textures/entity/player_wrist.png`
  （Spark content-pack 加载器从 mod 资源加载，crash log pack 列表已证实 `mod/catoxidesbattlerebuild` 在列）。

## 2. 跨客户端同步：结论与证据（本次调查核心）

### 2.1 Spark 网络层到底同步什么（反编译源码）

| Payload（spark_core 命名空间） | 方向 | 内容 | 发送方 |
|---|---|---|---|
| `anim_stop` | **双向** | 实体id + 层id → `stopAnimation(layer)`；服务端收到后向本维度全体玩家重播 | Spark 有发送逻辑 |
| `sync_model_index` | server→client | 实体id + ModelIndex → `setModel(index)` | **Spark 自身从不发送**（只实现了客户端 handler）——留给使用方 mod 手动发 |
| `anim_speed_change` | server→client | 实体id + time + speed | **Spark 自身从不发送**（同上） |
| 「播放动画」payload | — | **不存在** | — |

- `ModelIndexSyncPayload` 的客户端 handler 会把收到的 modelIndex 直接 `setModel(...)`；
  它**允许 null**，但对玩家发 null 会触发本次闪退同款 NPE → 若将来手动发，永远发具体索引。
- 手动发送方式（备用扩展点）：
  `PacketDistributor.sendToPlayersTrackingEntity(entity, new ModelIndexSyncPayload(
      SparkSyncerTypes.ENTITY.get(), new IntSyncData(entity.getId()), 我们的ModelIndex))`。
- Spark 的设计哲学：**动画不在网络上同步**。动画由每个客户端本地推导
  （内置状态机 / 数据驱动 animset / 本地代码），网络只同步实体状态。

### 2.2 为什么所有客户端能看到同一个叠加层（三层推导）

1. **Vanilla 同步层**：主手持物、挥击、移动/朝向、潜行/疾跑、离地（位置+速度）、皮肤、主臂——
   全部是 vanilla 同步状态，服务端中继，所有客户端看到一致。
2. **每客户端推导层**：
   - 我们的 handler 对**所有**玩家（本地+远程）跑同一套逻辑：持剑→激活、挥击→attack、移动→状态动画；
   - Spark 内置 `player_base_state` 状态机同样对每个客户端的每个玩家实体运行
     （`EntityJoinLevel` 注册、`EntityTickEvent.Post` tick），同输入→同状态→同状态动画。
3. **共享资源层**：模型/动画/贴图在 mod 资源里，所有装了同版本 mod 的客户端文件一致。

→ **结论：所有装了 mod 的客户端独立推导出完全相同的叠加层（同模型、同动画、同位置），
不需要 Spark 网络包，也不需要服务端跑任何 Spark 动画逻辑。**
用户要求「spark 仍要能跨 客户端-服务器-其他客户端 同步所有动画块位置（包括自定义）」
= 已满足：自定义骨/自定义动画在各端本地求值，位置一致性 = vanilla 状态一致性 + 相同 tick 时钟。

### 2.3 服务端角色

- 专用服务器：只中继 vanilla 状态，不渲染。服务端实体上 Spark 状态机/AnimController 也会跑
  （无害，无渲染消费）。第一步**零服务端代码**。
- 单人：integrated server，同一 JVM，天然一致。

### 2.4 未来逃生舱（当前不需要）

若日后动画触发变为**服务端权威**（无法由 vanilla 状态推导，如服务端指令变身、技能触发动画）：
- 模型切换 → 手动发 `ModelIndexSyncPayload`（§2.1 方式）；
- 停止某层 → `anim_stop`（双向，客户端可发起、服务端自动重播全维度）；
- 调速 → `AnimSpeedChangePayload`（server→client，手动发）。
剑挥击/状态动画目前均可由 vanilla 状态推导，不需要任何网络包。

## 3. 已知冲突与风险（多人实测前必读）

| # | 项 | 现状 | 处置 |
|---|---|---|---|
| 1 | **STATE 组(1)双驱动**：Spark 内置状态机也播 `state.*` 到 group 1，与我们的看门狗同组 | 双方关键帧同源（我们的状态动画就生成自 base_state.json）→ 视觉一致；但**疾跑/潜行/游泳/攀爬/鞘翅/坐/睡** 我们的模型没做对应动画 → 内置机静默放弃、旧动画滞留（疾跑时播 move 循环） | 第二步选项A：把 base_state.json 全套状态动画（sprint/move_back/crouch.*/swim.*/climb.*/fall_fly/sit/sleep/jump_land）生成进 player_wrist，STATE 完全交给内置机、撤掉我们的看门狗（更干净且获得全套状态）。选项B：激活期间关内置机（`StateMachineHandler.isActive` setter 是 Kotlin internal，Java 调用名 mangled，需 javap 验证） |
| 2 | **内置机 jump 状态 payload 在 group 4(MAIN)** | 跳跃时内置机把 state.jump 播进 MAIN 组（与 3rd_still 同组）——两者驱动不同骨（body系 vs 剑骨），按骨共存，视觉无害 | 记录在案；若改选项A（STATE 全交给内置机）则此点不变 |
| 3 | **远程玩家皮肤** | WristSkinComposer 对远程玩家读 `getSkin().texture()`（同步皮肤资源）；可解析→合成，不可解析→静态 Steve 回退（已实现）；多玩家时 DynamicTexture 会累积 | 建议：动态合成仅对本地玩家开放，远程一律静态复合贴图（第二步小改） |
| 4 | **F3+T 资源重载** | 动态贴图/Spark 模型可能失效，当前无自动恢复 | 第二步：监听资源重载事件 → 对所有激活玩家 deactivate+activate |
| 5 | **64×32 legacy 皮肤** | 回退静态 Steve（仅 debug 日志） | 需确认用户自己皮肤是否 legacy；是则加 64×32→64×64 重映射（贴图上半部 1:1、下半部 2x 采样） |
| 6 | **动画时钟** | 各端 AnimController 独立计数（同 tick 速率），位置在数个 tick 内一致 | 可接受（与 vanilla 挥击平滑同级） |
| 7 | **setModel(null) 陷阱** | 本次闪退根因；Spark 自己的 ModelIndexSyncPayload handler 对 null 也是裸 setModel | 全项目规则：**玩家模型永远非空**（用默认索引代替 null）；文档已记入 handler javadoc |
