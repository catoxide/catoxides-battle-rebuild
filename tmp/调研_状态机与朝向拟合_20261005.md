> 用户布置（10/05 睡前）：①客制动画的状态机 ②基于玩家指针方向（头朝向）的动画自动拟合
> （如头朝上挥剑时剑向头上运动）的可能性。具体动画内容用户醒来后定——本文只固化
> **机制、扩展点、可行路径**，不含具体动画设计。
>
> 源码基准：`tools\_spark_core_src\Spark-Core-1.21.1-neoforge\src\main\`

## 0. 结论先行

1. **客制状态机：完全可行，且 Spark 留好了正规扩展点。**
   - 最小改动：**`ChangePresetAnimEvent.PlayerState`**（游戏总线，可取消+可换 `newAnim`）
     ——状态机每次进入状态都发这个事件，Mod 可按"当前模型+状态名"替换要播的动画。
   - 完整方案：**`StateMachineRegisterEvent.Entity`** 注册**自定义 `StateMachineHandler`**
     ——每实体一个 handlers map，进场景时可注册任意 handler（Spark 自己注册了
     player_base_state / entity_base_use_state 两个），每 tick `progress()`。
     接口 `StateMachineHandler { machine: StateMachine?; isActive: Boolean; fun progress() }`
     ——**machine 可空**：可以不用 KStateMachines，Java 手写一个简单 FSM 实现接口即可。
   - 不可用：pack `animation_controllers`（`AnimStateModule`→`OAnimStateMachine`）——
     **transition 条件代码被注释掉了**（choiceState 永远返回原状态），状态机不会迁移，
     1.0.957 版本上别指望它驱动状态逻辑。
2. **朝向拟合：可行，且 Spark 自家就是先例。**
   - 事实：模型世界矩阵 = `translate(实体位置) × rotateY(π−身体偏航)`，**只有 yaw、没有
     pitch**（`IEntityAnimatable.getWorldPositionMatrix`）⇒ 身体/手臂天然不跟随俯仰。
     唯独 head 骨跟随完整视向——因为 Spark 自家 `BoneModifier` 在 `BoneUpdateEvent` 里
     对 "head" 骨注入 `(−player.xRot, −yHeadRot+yBodyRot, 0)` 弧度。
   - 方案：同一个机制，注入到剑链骨（推荐 **rightArm 肩骨**）：
     `内部旋转 x 分量 += −xRot·k`（k=跟随增益 0..1）。数学已按 JOML 约定推导
     （§2.3）：**加在 x 分量 = 绕肩骨父系 X 轴（=模型侧轴）过肩 pivot 的旋转，
     且对任意手臂动画姿态都稳定**（作用在父系坐标系，不随手臂自身旋转漂移）。
   - 落地位置：现有 `SwordPlayerModelHandler.onBoneUpdate`（已订阅同一事件、已做模型
     索引守卫）——加一个骨名分支即可，纯客户端、对一切现有/未来动画自动生效。
   - 分阶段：P1 静息姿态随俯仰 → P2（自动）挥击弧线随俯仰倾斜 → P3（可选）水平朝向
     跟随（剑指向头朝向而非身体朝向）。

## 1. 客制动画状态机

### 1.1 架构全图（已逐行核对）

```
EntityPatch（mixin 到所有实体）
  └─ IStateMachineHolder: stateMachineHandlers: MutableMap<ResourceLocation, StateMachineHandler>

StateMachineApplier（游戏总线，SparkCommonEventRegister 注册）
  ├─ EntityJoinLevelEvent → post StateMachineRegisterEvent.Entity(handlers, entity)
  │    └─ Mod 在此往 map 里注册任意 handler（Spark 自家：
  │       spark_core:player_base_state  → PlayerBaseAnimStateMachine（每个 Player）
  │       spark_core:entity_base_use_state → EntityBaseUseAnimStateMachine（每个 LivingEntity））
  └─ EntityTickEvent.Post（HIGHEST）→ 每个 isActive 的 handler.progress()

StateMachineHandler 接口：{ machine: StateMachine?; isActive: Boolean; fun progress() }
  （machine 可空 ⇒ 手写 FSM 实现 progress() 即可，不必依赖 KStateMachines）

动画层（AnimController，每模型实例一个）
  ├─ layers: Map<group, AnimLayer>；AnimGroups: STATE=1, DECOR=2, MAIN=4
  │    混合按 group 升序：STATE→DECOR→MAIN；weight=1 的组完全覆盖前组（OVERRIDE lerp）
  ├─ physTick（物理线程）：每骨 blendBone() → bonePose.updateInternal()
  │    （未被任何层提到的骨 = pos 0 / rot 0 / scale 1 重置）
  └─ tick（主线程）：每骨 setChanged() → NeoForge.EVENT_BUS.post(BoneUpdateEvent)
       → 全部监听器改 event.newTransform → localTransform = event.newTransform

AnimInstance（一个动画实例 = 一个组里的一条动画）
  ├─ 生命周期 FSM：idle→enter(权重 ramp)→work→exit→idle
  │    事件：Start / Interrupted / Completed / End / Tick（可 onEvent 监听！）
  ├─ loop：TRUE / ONCE / HOLD_ON_LAST_FRAME
  ├─ enter() / exit() / independentEnter()（先 stopAnimation(group) 再 enter）
  └─ origin.timeline 脚本：动画 JSON 时间线上的 Molang/JS 在 enter 时 eval——数据驱动钩子
```

### 1.2 PlayerBaseAnimStateMachine 行为（玩家内置状态机）

- 图结构：`none → base { initialChoice: sit / sleep / fall_fly / fall / jump /
  jump_land / climb{idle,move} / swim{idle,move,move_back,sprint} / crouch{...} /
  fly{...} / land{idle,move,move_back,sprint} }`
- `progress()` = `processEventBlocking(SwitchEvent)` → `transitionOn<SwitchEvent>{target=base}`
  ——**每 tick 重走 initialChoice**（状态跟随玩家情境的机制）。
- `JumpEvent` 由 `LivingJumpEvent` 监听器发出（仅本地玩家）→ jump 态；
  jump 态 `payload = AnimPayload(0f, AnimGroups.MAIN)` ⇒ **"state.jump" 播在 MAIN 组**
  （其余状态默认 STATE 组）。`FallEvent` 监听器目前被注释掉。
- `onStateEntry` → `playRelativeAnim("state." + 状态名)`：
  1. `animInstance(player, 动画名, false)` 从**当前模型**动画集解析（缺失 → null，静默跳过）；
  2. **post `ChangePresetAnimEvent.PlayerState(player, originAnim, state)`**——
     `ICancellableEvent`（可取消=该状态不播任何动画）+ `newAnim` 可替换；
  3. group = 状态 payload 的 group，否则 STATE；退出上一个状态动画（非 Loop.ONCE 才退出）、进入新的。
- 20 个状态名 ↔ base_state.json 的 20 个动画名一一对应（state.land.idle、state.land.move、
  state.land.move_back、state.land.sprint、state.crouch.*、state.fly.*、state.swim.*、
  state.sit、state.fall_fly、state.sleep、state.fall、state.jump_land、**state.jump**、
  state.climb.*）。

### 1.3 三条扩展路径对比

| 路径 | 机制 | 优点 | 缺点 | 适用 |

## 2. 朝向驱动动画拟合（剑随头向运动）

### 2.1 管线事实（为什么需要自己注入）

- `IEntityAnimatable.getWorldPositionMatrix`：`translate(实体插值位置) × rotateY(π − 精确身体偏航)`
  ——**模型根只有 yaw；玩家俯仰（xRot）在 Spark 管线中完全缺席**（全库 grep：pitch/xRot
  仅出现在 BoneModifier、EntityTurnEvent、状态机爬梯限制等处，无根矩阵 pitch）。
- 原版参照：第三人称 = 身体 yaw 追踪视向（yBodyRot 缓慢 lerp），模型**不带 pitch**
  （所以原版三视角拉弓是"身体转过去、手臂水平"）；第一人称 = `ItemInHandRenderer`
  相机空间画手臂，天然贴准星。我们做的是"三视角剑跟随视向"——超原版表现，必须自注入。
- 唯一例外 head 骨：Spark 自家 `BoneModifier.head`（游戏总线 BoneUpdateEvent 监听器）
  `rotation += (−player.xRot, −player.yHeadRot + player.yBodyRot, 0)` 弧度
  ⇒ **"用 BoneUpdateEvent 把玩家视向注入某骨"是 Spark 的既有实践**，我们照抄即可。

### 2.2 注入点与数学（已按 JOML 约定推导）

骨局部矩阵（`BonePose.getLocalTransformMatrix`）：
`T(pivot)·T(pos)·rotateZYX(局部旋转 + 骨静态旋转)·scale·T(−pivot)`
其中 `rotateZYX(v) = Rz(v.z)·Ry(v.y)·Rx(v.x)`（JOML 约定，见缩放定论 §11）。

**关键恒等式**：在内部欧拉 x 分量上加 Δ（`ix → ix+Δ`）：
`R' = Rz(iz)·Ry(iy)·Rx(ix+Δ) = R·Rx(Δ)`（有骨静态旋转偏移时同样成立，偏移只平移基准）。
矩阵乘右结合 ⇒ `Rx(Δ)` 作用在**骨自身旋转之前的局部系 = 父系（平移到 pivot+pos）**。

| 注入骨 | pivot | Δ 的实际几何 | 稳定性 |
|---|---|---|---|
| **rightArm（肩，推荐）** | (−5, 21.5, 0) | 绕**模型侧轴（X）过肩点**的旋转 = 肩俯仰：整条手臂+剑抬起/压向视向 | 父系=waist→body（基本无旋转）⇒ **任意手臂动画下轴都不漂移** |
| rightItem（腕） | (−5.5, 12.5, 0) | 绕腕系 X（随手臂动画旋转）的旋转 = 剑相对手抬起 | 轴随挥击姿态漂移——适合"手位不动、剑指向目标" |
| main（剑根，父 right→hands→rightItem） | (−5.5, 12.5, 0)（=腕） | 同腕但更深一层（父链被 3rd_still/attack 动画驱动） | 用于剑相对握柄微调 |

**符号**：MC xRot 正 = 低头（与 head 注入同款约定：`−xRot` ⇒ 抬头时 +x）。
剑注入式：`内部旋转.x += −xRot · k`（k = 跟随增益，0=关、1=完全跟随）。
最终符号以 2 秒游戏内 A/B 确认（持剑抬头/低头看剑尖方向）。

**数据源**：`player.getXRot()`（客户端 AbstractClientPlayer，本地+远程玩家均有同步值——
BoneModifier 对任意 LivingEntity 用同样字段）；水平向用 `yHeadRot − yBodyRot`。

**与其他机制的交互（已核）**：
- 0.9375 root 钳制：不同骨，无交互（同一事件链上各自改各自骨的 newTransform）。
- 动画：事件在 blend 之后 ⇒ 注入叠在任何动画之上（still/attack/未来一切），
  无需改任何动画文件。
- `BoneModifier.sleep`：只动 root 骨且仅睡觉时，无交互。
- 幅度保护：Δ 建议 clamp 到 ±60°（极端俯仰时防过旋）。
- rightArm 现在只有 MAIN 组驱动（状态动画已剔 rightArm）⇒ 注入基底干净。

### 2.3 分阶段路径（具体参数等用户定动画时再调）

- **P1 静息随俯仰**：`onBoneUpdate` 对 player_wrist 的 rightArm 骨
  `rotation.x += clamp(−xRot·kStill, ±60°)`（kStill≈0.5–1 起步）。
  效果：站着抬头看天，剑臂+剑整体抬向头顶方向（用户描述的"头朝上挥剑时剑向头上运动"的静息版）。
- **P2 挥击随俯仰（自动免费）**：同一注入在 3rd_attack 播放时同样生效（事件与姿态无关）
  ⇒ 挥击弧线平面随俯仰倾斜。可加条件增益：仅 attack 播放时 kSwing（用现有
  `isPlaying(MAIN, "3rd_attack")` 判断，或阶段 2 状态机知道当前状态）。
- **P3 水平朝向跟随（可选）**：`rotation.y += (yHeadRot − yBodyRot)·kYaw`——
  剑指向头朝向而非身体朝向（head 骨 Spark 已原生这么做；给剑链补齐）。
- **验证协议**：游戏内 A/B——平视/抬头 45°/低头 45° ×（静息/挥击）对比剑尖方向 vs 视向；
  需要时加 `[测向]` 日志（打印注入前后 rightArm 欧拉 + xRot）。
