## 四、编译期发现与决策（10/07 构建实录）

1. **Spark 不在 pack 编译类路** → MANIFEST 加 `Module-Lib-Requires: spark` +
   `contentpacks-source/_libs/spark/spark-core.jar`（从 libs/ 拷贝；ContentPackLoader 的
   _libs 机制把它挂到 pack compileOnly，运行时走父类路）。
2. **FML 类不在 pack 编译类路**（maven `net.neoforged:neoforge` 只含 neoforge.* 包）。
   包内原写的 `FMLEnvironment.dist == Dist.CLIENT` 与 `ModConfig.Type.SERVER` 全部改走 core 桥
   （Constants.CLIENT / registerServerConfig）。顺带核实 FQN：`FMLEnvironment` 实际在
   **net.neoforged.fml.loading**（loader jar，javap 确认 `public static final Dist dist`），
   `Dist` 在 net.neoforged.api.distmarker（mergetool-api jar）——core 类路有、pack 类路无。
3. **CombatConfig.register(ModContainer) 死方法删除**（唯一调用点已删；直接引用 FML 类型，
   包内编译不过）。配置值惰性读取的约束不变。
4. **OBBRenderer 留 core 共享**（侦察遗漏第 3 件）：client/renderer/ 第三个文件，
   纯绘制工具（OBB/轴线），core 的 BoneDebugRenderer（留 core）与包内
   SwordHitboxDebugRenderer 双消费者 → 不复制、不迁移，包内 import core 版本
   （pack→core 引用合法，与 LogManager/HitboxResolver 同模式）。
5. 构建：`:packs:melee-combat-pack:contentpackJar --offline` BUILD SUCCESSFUL；
   `compileJava --offline` BUILD SUCCESSFUL。jar = 34 顶级类 + 11 内部类；MANIFEST 六键齐全，
   Module-Requires 的 modid 22 字符拼写程序化核实通过。
