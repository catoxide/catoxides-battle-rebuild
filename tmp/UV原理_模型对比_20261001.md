# 叠加层模型「为什么一直不像原版」— 原理报告（2026-10-01）

> 目的：固化「和原版/Spark 用同一套模型」的原理，钉死每个部位的 UV 事实，回答用户的核心疑问——**为什么做了 4-5 个版本，角色模型一直和原版（手持普通物品时）不一样？**
> 证据：① 反编译 Spark `OPolygon.of` 的 box-UV 展开公式（`tools\_spark_src\...\OPolygon.java`）② Spark 9 骨 vanilla 参考 `D:\OpenCodeTemp\player_vanilla.json`（含 box-UV）③ 我们的 `player_wrist.json`（含逐面 face-UV）④ `uv_diff2.cjs` 逐面精确 diff ⑤ 逐像素扫描 STEVE.png / efe.png 验证布局。

## 一句话结论
我们的分节模型 UV 是从 Spark 的 `steve.json` 抄来的，而 **steve.json 的 UV 是为它捆绑的 `_steve.png` 设计的，不是为标准皮肤布局设计的**。换到玩家真实皮肤（标准布局）后，多处 UV 采错区。最要命的两个：
1. **左臂 / 左腿映射到了内层（和右臂右腿同区），但原版左臂左腿在「外层（帽层）」。** → 左臂左腿采到的是右臂右腿的纹理。
2. **头 / 躯干的 east 与 west 两面互换了，down 面 y 坐标也错了。**

## 一、原版玩家模型的事实（ground truth）

vanilla PlayerModel 是 **6 个刚性部件，无肘/膝**（`player_vanilla.json` 的 9 骨参考即此几何）：

| 部位 | box-UV (u,v) | 所在层 | 几何 size |
|---|---|---|---|
| head 头 | (0,0) | 内层 y0-32 | 8×8×8 |
| waist 躯干 | (16,16) | 内层 y0-32 | 8×12×4 |
| rightArm 右臂 | (40,16) | **内层** y0-32 | 4×12×4（单块） |
| leftArm 左臂 | (32,48) | **外层** y32-64 | 4×12×4（单块） |
| rightLeg 右腿 | (0,16) | **内层** y0-32 | 4×12×4（单块） |
| leftLeg 左腿 | (16,48) | **外层** y32-64 | 4×12×4（单块） |

**关键不对称**：右臂/右腿/头/躯干在**内层**，左臂/左腿在**外层（帽层 y32-64）**。这是标准 64×64 皮肤布局的固有设计（1.8 起「帽层算整个身体」）。

## 二、Spark box-UV 展开公式（反编译实证）

`OPolygon.of`：box 原点 (u,v)、像素尺寸 (a,b,c)（JSON size 即像素，1 模型单位=1px），构造
`X=[u, u+c, u+c+a, u+c+2a, u+2c+a, u+2c+2a]`，`Y=[v, v+c, v+c+b]`，按 Direction 取：

| 面 | 方向 | 原点 | 尺寸 |
|---|---|---|---|
| east | +X (case1) | (u+c+a, v+c) = (X[2],Y[1]) | c×b |
| west | −X (case2) | (u, v+c) = (X[0],Y[1]) | c×b |
| north | −Z (case3) | (u+c, v+c) = (X[1],Y[1]) | a×b |
| south | +Z (case4) | (u+2c+a, v+c) = (X[4],Y[1]) | a×b |
| up | +Y (case5) | (u+c, v) = (X[1],Y[0]) | a×c |
| down | −Y (case6) | (u+c+a, v) = (X[2],Y[0])，v 翻转 | a×c |

用头 (0,0,8,8,8) 验证：north(8,8)前 / south(24,8)后 / west(0,8)左 / east(16,8)右 / up(8,0)顶 / down(16,0)底 —— 与标准头布局完全吻合，公式正确。

## 四、根因（为什么 4-5 个版本都不对）
1. **源头错了**：UV 抄自 `steve.json`，它服务于 `_steve.png`（一张帽子层被设计成与内层一致的特殊贴图），对真实玩家皮肤不成立。
2. **左臂/左腿层次错**：我此前的 `LIMB_UV_FIX` 把 8 个肢体全指到**内层**，但原版左臂/左腿在**外层**。对称皮肤（STEVE）看不出，但用户皮肤 efe **左臂蓝 / 右臂棕**、腿若左右异色 → 左臂左腿永远显示成右侧的纹理 → 「上臂下臂不一致」的真正来源之一。
3. **头/躯干 east/west 互换 + down y 错**：这两处不在上次 `LIMB_UV_FIX` 范围内（只修了 8 个肢体），仍是 steve.json 原值 → 头会被镜像（发胶/偏分跑到另一侧）、躯干侧面镜像。
4. **几何次要差异**：我们手臂宽 3.5（原版 4，略细 0.5px）；分节（肘/膝）在静止位不可见、动画时才显现（这是分节模型的本意，非 bug）。

### 7.1 关键结论：face-UV 的正确形态 = 原版 box-UV 矩形原样（正宽）
对**非镜像 cube**，`OPolygon.init` 两个分支对同一顶点序的角点映射是：
- **box-UV 分支**（原版）：构造传入 (u1=左, u2=右, v1=上, v2=下)，init 内 `!mirror` **先交换 u1/u2**，再 W0←(u1,v1) W1←(u2,v1) W2←(u2,v2) W3←(u1,v2) ⇒ 实际 W0←(右,上) W1←(左,上) W2←(左,下) W3←(右,下)
- **face-UV 分支**（我们）：`mirror=false` 不换，W0←(u+w,v) W1←(u,v) W2←(u,v+h) W3←(u+w,v+h)

两分支像素级相同 ⇔ **face-UV = uv:[左,上] size:[宽,高]（正宽）**；down 面 v2<v1 ⇒ h 为负、**锚点在下沿 V1**。
⇒ **§五"翻转符号：右臂/左腿负宽"是错的**：负宽会把采样区平移 |w|=4px（右臂 west 面采到躯干 south 右半、leftLeg west 面采到空白区）；且旧表所有 down 面锚点锚在上沿（v 错 4-8px，采到错误行）。10/01 的 `uv_diff2.cjs` 对肢体只打印未判 MATCH（2 cube 分支无裁决），"36 面全对齐"结论不成立——实为 32/60 面错。

旧分段模型为什么"和原版不一样"（根因，源码级）：
1. **rightArm 语义被破坏**：原版/Spark 基线里 `rightArm` = 整条臂（走路时整臂 ±摆动）。旧模型 rightArm 只是上臂（4×6），前臂是独立骨 rightForeArm 且 STATE 动画不驱动它 → 走路时整臂该摆的角度只发生在上臂，前臂保持静止 → 手臂在肘部弯折、形态怪异（用户看到"模型不一致"的直接来源之一）。
2. **body 骨缺失**：旧模型把 body 合并进 waist。原版 `state.land.move` 会驱动 body 骨（bob/前倾），合并后躯干前倾与腿不再联动。
3. **UV 补丁链本身脆弱**（§七）：60 面手推 face-UV，任何推导错误都表现为"贴图串位"。
⇒ 1:1 身体同时修复 几何 + 动画语义 + UV（原版 box-UV 原样）三件事。
